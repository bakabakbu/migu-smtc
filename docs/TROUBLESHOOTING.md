# 排障手册

按顺序往下走，绝大多数问题在第 2 步就能解决。

---

## 第 1 步：确认脚本在跑

| 检查项 | 怎么做 | 正常结果 |
|---|---|---|
| 脚本猫「允许使用者脚本 / 开发者模式」已开 | 脚本猫 → 设置 | 开关为开启状态 |
| 脚本已启用且作用在咪咕域名 | 脚本猫 → 脚本列表 | 显示启用，匹配 `*://music.migu.cn/*` |
| 页面已刷新 | 打开咪咕后按 F5 | — |

打开「调试日志」开关并刷新页面后，**控制台没有任何 `[咪咕SMTC]` 开头的日志** → 说明脚本没注入，回头检查上表三项。

---

## 第 2 步：一键诊断（最关键）

脚本猫菜单 → **咪咕SMTC · 一键诊断** → F12 控制台看到：

```text
===== 咪咕SMTC 诊断报告 =====
播放条：... → 命中
歌名：... → 命中，取值：xxx
歌手：... → 命中，取值：xxx
封面：... → 命中，取值：https://...
按钮：... → 命中，播放中：true
已上报给系统：xxx - xxx
当前缓存：xxx - xxx
============================
```

**怎么读**：哪一项显示「未命中」，就是咪咕改版后变了位置的元素，需要换对应选择器（见第 3 步）。

---

## 第 3 步：换新选择器（咪咕改版时）

1. 在咪咕页面上，**右键**出错的那个元素（例如歌名）→ **检查**；
2. 在弹出的开发者工具里，找到蓝色高亮的那行 HTML，看它的 `class="..."`；
3. 脚本猫 → 配置面板 → 把对应选择器改成 `.那个class`；
   - 歌名参考：`.footer-player .song-name`
   - 歌手参考：`.footer-player .singers`
   - 封面参考：`.footer-player .default-cover img`（必须指向 `<img>` 元素本身）
   - 按钮参考：`.footer-player .custom-icon`
4. 保存 → 刷新页面 → 再跑一次诊断。

> 选择器写法很简单：`.` 开头表示 class，空格表示「里面的」。例如 `.footer-player .song-name` = 播放条里面的歌名。

---

## 第 4 步：常见现象对照表

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 完全没反应 | 脚本猫「允许使用者脚本」未开启 | 开启后刷新 |
| 卡片空白（无歌名） | 歌名选择器失效或歌没在播 | 诊断 → 换选择器 |
| 有歌名没歌手 | 歌手选择器失效 | 换歌手选择器 |
| 有歌名没封面 | 封面选择器没指向 `<img>` | 选择器末尾加 ` img` |
| 显示**别的歌**的封面 | 咪咕换封面比换歌名慢 | 等数秒会自动纠正 |
| 最小化时不更新 | Chromium 会冻结不可见窗口（已知限制） | 不要最小化，改为被其他窗口盖住；或给 Edge 加 `--disable-background-timer-throttling` 等启动参数 |
| 媒体键无反应 | 控制按钮选择器失效 | 换按钮选择器 |
| 一直显示「暂停」 | 按钮 title 文案变了 | 诊断里看「播放中」是否为 true，不为 true 则换按钮选择器 |

## 第 5 步：需要提供信息求助时

请把以下三样一次性贴到 [Issue](https://github.com/bakabakbu/migu-smtc/issues/new/choose)：

1. **一键诊断的完整输出**；
2. **打开调试日志后复现过程的 `[咪咕SMTC]` 日志**（整段复制，不要只截图）；
3. **运行环境**：Windows 版本 + 浏览器及版本 + 脚本猫版本。
