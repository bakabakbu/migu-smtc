# tools/ · 排查用探针

这里放的是**临时排查脚本**——不是主脚本的一部分，只在需要重新摸清咪咕网页结构时才用。

**用法通用三步**：

1. 记事本打开对应文件 → 全选复制；
2. 打开咪咕页面 → F12 → Console → 粘贴回车（首次粘贴可能需输入 `允许粘贴`）；
3. 把输出的结果整段复制出来分析。

> 这些脚本**只读不写**，不改变页面任何内容，用完关掉页面即失效。

---

## probes/ · 侦察探针（按开发顺序）

| 文件 | 用来查什么 | 什么时候用 |
|---|---|---|
| `probe-selectors.js` | 页面上有哪些疑似"歌名/歌手/封面"的元素及其 class | 咪咕大改版、选择器全失效时，**先跑这个** |
| `probe-player.js` | 播放条（`.footer-player`）是否命中、页面有无 `<audio>`、播放大页元素 | 需要确认播放条结构时 |
| `probe-player3.js` | 播放条内部的**完整 HTML 结构**，含每个元素的嵌套关系 | 要精确定位歌名/歌手/封面在哪一层时 |
| `probe-network.js` | 切歌时咪咕发出的网络请求 | 想从"网络数据"绕开界面取值时 |
| `probe-vue.js` / `probe-vue2.js` | Vue 应用的状态账本（Vuex / Pinia / 组件树 / localStorage） | 想拿"不依赖界面刷新"的数据源时 |
| `probe-amber.js` | 咪咕每秒的播放上报（含歌名、歌曲编号） | 需要确认"当前正在播哪首"的权威信号时 |
| `probe-media.js` | 咪咕打印的完整歌曲档案（歌名/歌手/专辑/封面/歌词） | 需要一次性拿到歌曲全部字段时 |

---

## 已知结论（避免重复侦察）

- 咪咕播放全程**没有 `<audio>` 元素**，播放状态只能靠按钮文案反推；
- 切歌时**通常不产生新的网络请求**（歌单信息早已整批下载）；
- Vue 的公共状态账本（Vuex / Pinia）**未对外暴露**；
- 咪咕的日志模块会**提前保存 `console.log` 引用**，事后再包装控制台无法拦截其输出。

以上每一条都花过实际时间验证，**后续遇到同类问题请先对照再动手**。
